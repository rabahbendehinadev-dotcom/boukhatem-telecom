صح، نفس المشكل مازال: **الصورة تترفع ويبان Preview داخل الفورم، بصح الرابط النهائي لي يتسجل في قاعدة البيانات أو يرجع من الـAPI راهو خاطئ/مؤقت**. لهذا في الأدمن والواجهة يبان Alt Text فقط: `COMING SOON`.

ابعث له هذا البرومبت، راهو مركز على السبب الحقيقي:

```text
مازال نفس مشكل البانر موجود.

الصورة تظهر بنجاح داخل نافذة التعديل مباشرة بعد Upload، لكن بعد الحفظ:

- تظهر صورة مكسورة داخل بطاقة البانر في لوحة الإدارة.
- يظهر فقط Alt Text مثل COMING SOON.
- في الصفحة الرئيسية تظهر الخلفية بدون صورة البانر.
- هذا يعني أن Preview المحلي يعمل، لكن رابط الصورة النهائي المحفوظ أو المسترجع من الـAPI غير صالح.

أريد منك تشخيص وإصلاح المشكلة من المصدر، وليس إضافة Fallback أو Gradient لإخفائها.

━━━━━━━━━━━━━━━━━━━━━━
1. افحص القيمة الحقيقية بعد الحفظ
━━━━━━━━━━━━━━━━━━━━━━

بعد الضغط على Enregistrer، اطبع مؤقتًا في Server Logs وBrowser Console:

- قيمة imageUrl قبل الحفظ.
- القيمة التي تُحفظ في PostgreSQL.
- القيمة التي يعيدها API بعد الحفظ.
- رابط الصورة النهائي الذي يوضع داخل src في React.

أريد التأكد هل القيمة المحفوظة هي:

blob:...
data:...
/uploads/...
uploads/...
اسم ملف فقط
أو مسار محلي داخل السيرفر.

يمنع حفظ روابط Preview المؤقتة من نوع:

blob:http://...
URL.createObjectURL(...)
data:image/...

هذه الروابط تعمل فقط أثناء الجلسة ولا تصلح بعد الحفظ.

━━━━━━━━━━━━━━━━━━━━━━
2. افصل Preview عن الرابط النهائي
━━━━━━━━━━━━━━━━━━━━━━

استعمل Preview محلي فقط للمعاينة قبل الرفع.

بعد رفع الملف إلى Backend، يجب أن يعيد Backend رابطًا دائمًا مثل:

/uploads/banners/uuid-name.webp

ثم يتم حفظ هذا الرابط الدائم فقط داخل قاعدة البيانات.

مثال لتدفق صحيح:

1. المستخدم يختار الصورة.
2. Frontend يرسل FormData إلى API Upload.
3. Backend يحفظ الملف.
4. Backend يعيد:
{
  "url": "/uploads/banners/file-name.webp"
}
5. Frontend يضع هذه القيمة في imageUrl.
6. عند Enregistrer يتم حفظ imageUrl الدائم داخل PostgreSQL.

لا تحفظ رابط المعاينة المحلي.

━━━━━━━━━━━━━━━━━━━━━━
3. افحص API رفع الصور
━━━━━━━━━━━━━━━━━━━━━━

تحقق أن Endpoint الرفع يعيد JSON واضحًا:

POST /api/admin/uploads/banners

النتيجة:

{
  "success": true,
  "url": "/uploads/banners/filename.webp",
  "filename": "filename.webp"
}

ثم تأكد أن Form البانر يستعمل response.url وليس previewUrl.

━━━━━━━━━━━━━━━━━━━━━━
4. تقديم مجلد uploads للمتصفح
━━━━━━━━━━━━━━━━━━━━━━

تأكد أن Express يقدم الملفات Static:

import path from "path";
import express from "express";

app.use(
  "/uploads",
  express.static(path.resolve(process.cwd(), "uploads"))
);

إذا كان مجلد الصور داخل مسار آخر، استعمل المسار الحقيقي الصحيح.

اختبر الرابط مباشرة في المتصفح:

https://repairephonedz.com/uploads/banners/filename.webp

يجب أن تفتح الصورة وحدها بدون:

- 404
- 403
- صفحة HTML
- إعادة توجيه إلى Login

مجلد /uploads يجب أن يكون عامًا للقراءة، لكن الرفع يبقى محميًا للأدمن.

━━━━━━━━━━━━━━━━━━━━━━
5. توحيد بناء رابط الصورة
━━━━━━━━━━━━━━━━━━━━━━

أنشئ Utility واحدة فقط مثل:

getMediaUrl(path)

وظيفتها:

- إذا كان الرابط يبدأ بـ http:// أو https:// تعيده كما هو.
- إذا كان يبدأ بـ /uploads تعيده مع API base URL الصحيح عند الحاجة.
- تمنع تكرار الدومين.
- تمنع تكوين روابط مثل:
  /api/uploads/...
  /uploads/uploads/...
  undefined/uploads/...

استعملها في:

- بطاقة البانر داخل Admin.
- نافذة تعديل البانر.
- Hero Carousel في الصفحة الرئيسية.
- Mobile Banner.
- جميع الصور المرفوعة مستقبلًا.

━━━━━━━━━━━━━━━━━━━━━━
6. افحص اسم الحقل
━━━━━━━━━━━━━━━━━━━━━━

تحقق أن نفس اسم الحقل مستعمل في كل الطبقات:

Database:
imageUrl

Backend response:
imageUrl

Frontend:
banner.imageUrl

لا أريد وجود اختلاف مثل:

image
image_url
imagePath
desktopImage
bannerImage
imageUrl

إذا كانت الأسماء مختلفة، وحّدها أو اعمل mapping واضح.

━━━━━━━━━━━━━━━━━━━━━━
7. افحص البيانات بعد GET
━━━━━━━━━━━━━━━━━━━━━━

افحص نتيجة:

GET /api/banners
GET /api/admin/banners

وتأكد أن كل Banner يرجع مثل:

{
  "id": 1,
  "title": "COMING SOON",
  "subtitle": "...",
  "imageUrl": "/uploads/banners/xxx.webp",
  "buttonText": "Découvrir",
  "destinationUrl": "...",
  "displayOrder": 0,
  "visible": true
}

أريد التأكد أن imageUrl ليس null أو فارغًا.

━━━━━━━━━━━━━━━━━━━━━━
8. لا تعرض الخلفية بدل الصورة
━━━━━━━━━━━━━━━━━━━━━━

في Hero Carousel، لا تعتبر الـGradient صورة ناجحة.

إذا imageUrl موجود:

- اعرض الصورة بـ background-image أو img.
- استعمل object-fit: cover.
- استعمل background-position: center.

إذا فشل تحميل الصورة:

- سجل رابط الصورة والخطأ في Console أثناء التطوير.
- أظهر Fallback واضح فقط بعد معرفة الخطأ.

لا تخفِ المشكلة بخلفية Gradient.

━━━━━━━━━━━━━━━━━━━━━━
9. معالجة Cache
━━━━━━━━━━━━━━━━━━━━━━

بعد الحفظ أو تعديل الصورة، قم بعمل invalidate لكل Queries الصحيحة:

- ["admin-banners"]
- ["banners"]
- ["homepage-banners"]

وتأكد أن Browser لا يعرض رابط الصورة القديم.

عند استبدال صورة بنفس الاسم، استعمل اسم ملف UUID جديد أو أضف version query.

━━━━━━━━━━━━━━━━━━━━━━
10. اختبارات إلزامية
━━━━━━━━━━━━━━━━━━━━━━

لا تعتبر المهمة مكتملة حتى تنفذ وتعرض نتائج هذه الاختبارات:

1. ارفع صورة جديدة.
2. خذ الرابط النهائي الذي رجع من Backend.
3. افتح الرابط مباشرة في نافذة جديدة.
4. تأكد أن HTTP status هو 200.
5. احفظ البانر.
6. أعد تحميل صفحة الإدارة Refresh كامل.
7. تأكد أن الصورة مازالت تظهر في البطاقة.
8. أعد تحميل الصفحة الرئيسية.
9. تأكد أن نفس الصورة تظهر داخل Hero.
10. أعد تشغيل التطبيق.
11. تأكد أن الصورة مازالت موجودة ولم تختف.

أعطني في نهاية التنفيذ:

- الرابط النهائي المحفوظ.
- القيمة الموجودة في قاعدة البيانات.
- Status Code عند فتح الصورة.
- سبب الخطأ القديم بالتحديد.
- الملفات التي قمت بتعديلها.

مهم جدًا:

المشكلة ليست في أبعاد الصورة، لأن الصورة 1920×700 صحيحة.
المشكلة في تخزين أو تقديم أو استرجاع رابط الصورة الدائم.
لا تغيّر التصميم، أصلح مسار الصورة ورفعها بشكل فعلي.
```

ومن الصور باين أن البانر نفسه موجود والـtitle يخدم، يعني **الـAPI تاع البانرات راهو يخدم، والمشكل محصور في `imageUrl` أو Static uploads**. أكثر احتمال راهو يحفظ `blob:` تاع الـPreview بدل الرابط الدائم.
